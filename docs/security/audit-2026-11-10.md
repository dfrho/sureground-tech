## The change under review

`lib/security/headers.ts` `noindexRule()` returns a `next.config.ts` header rule: `source: "/:path*"`, `missing: [{ type: "host", value: "(www\.)?sureground\.tech" }]`, header `X-Robots-Tag: noindex, nofollow`.

- **Allowlist, fails safe:** Next.js matches `has` and `missing` values as a whole-string regular expression. Any host that does not exactly match gets `noindex`: vercel.app domains, deployment URLs, localhost, a missing Host header, and look-alikes such as `sureground.tech.evil.example` or `evilsureground.tech`. Unit tests in `tests/unit/headers.test.ts` cover these. Only the custom domain loses the header.
- **Host is client-controlled, but not exploitable here.** A client can send any Host header, but the only effect is whether that client's own response carries `noindex`. On Vercel, Host also selects the project, so a request naming `sureground.tech` only reaches this deployment once that domain is attached to it. No security decision depends on this header.
- **No interaction with other controls:** the rule adds one response header. The CSP, the other security headers and the proxy origin check are unchanged. `tests/e2e/security.spec.ts` checks that localhost responses (pages and `security.txt`) carry the header and that requests for `sureground.tech` and `www.sureground.tech` do not.

## Recommendations (not findings)

These are hardening steps for the now-public repository and the deployment, not identified weaknesses:

1. **Turn on GitHub secret scanning and push protection.** Both are free for public repositories and were off on 2026-11-09. No secret is in the repo today, but from Phase 4 on the Turnstile, Upstash and Resend keys exist, and push protection blocks a key from ever being pushed by mistake. Owner: David (repository setting; Claude can enable it on request).
2. **Turn on Dependabot security updates.** Version updates are on; security updates (pull requests raised from advisories) were off. `pnpm audit:deps` in CI already fails on High, so this only shortens the time to a fix. Owner: David.
3. **Raise pnpm `minimumReleaseAge` to 7 days** as planned in `docs/decisions.md`; the lockfile has now aged past the reason it was lowered. Owner: Claude, next dependency update.

## Limitations

- Static review. Deployed headers were confirmed on production for the Phase 1 build only (CSP, HSTS and X-Frame-Options observed on `sureground-tech.vercel.app`). The noindex header on production is checked after this branch deploys.
- Vercel's handling of `X-Forwarded-Host` and Host routing is platform behavior and was not tested here.
- Account settings (MFA, GitHub security features beyond those observed via the API) were not verified.
