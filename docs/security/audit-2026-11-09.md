# OWASP Top 10:2025 audit, Phase 0 foundation

- **Date:** 2026-11-09
- **Standard:** OWASP Top 10:2025, all ten categories
- **Scope:** `proxy.ts`, `next.config.ts`, `lib/security/*`, `lib/env.ts`, `lib/env.public.ts`, `lib/env.schema.ts`, `lib/config/*`, `app/**`, `scripts/*`, `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `.github/**`, `.gitignore`, `.env.example`
- **Method:** static review. The audit itself ran no project code. Separately, as normal Phase 0 work, the project's own checks were run (`pnpm test`, `pnpm test:e2e` against a local production build, `pnpm audit:deps`); their results are cited where relevant and labelled as such.
- **Execution contexts:** `proxy.ts` is server (Next.js 16 proxy, Node.js runtime, cannot be Edge). `next.config.ts` and `scripts/*` are build. `app/layout.tsx`, `app/page.tsx` and `app/.well-known/security.txt/route.ts` are server (Server Components and a route handler; no `"use client"` files exist). `lib/env.ts` is server (guarded by `server-only`). `lib/env.public.ts` and `lib/config/*` may be bundled for the browser and contain no secrets. `.github/**` is CI.

## Summary

The Phase 0 foundation has no user input surfaces: no forms, no Server Actions, no authentication, no database, no outbound requests. The attack surface is the HTTP layer (headers, CSP, request filtering), configuration, and the supply chain. That layer is in good shape: nonce-based CSP without `unsafe-inline` or `unsafe-eval` for scripts in production, the full required header set, a fail-closed same-origin check on all state-changing requests, exact dependency versions, a committed lockfile, SHA-pinned Actions with read-only token permissions, and an install-script deny list.

Three Low findings were found and **fixed during this audit**. Two Informational items remain as accepted, documented choices.

## Findings

### A01:2025 Broken Access Control

#### OWASP-A01-001: Proxy matcher let requests carrying prefetch headers skip the origin check (fixed)

- **CWE:** [CWE-352 Cross-Site Request Forgery](https://cwe.mitre.org/data/definitions/352.html)
- **Severity:** Low. There is no state-changing endpoint or session yet, and a browser cannot add `next-router-prefetch` or `purpose` to a cross-site request without a CORS preflight the site never approves, so the bypass is not reachable by a CSRF attacker today. It would weaken the fail-closed Origin check once Server Actions exist.
- **Confidence:** High. Matcher semantics read from the bundled Next.js 16.4.5 docs (`proxy.md`, `content-security-policy.md`).
- **Location:** `proxy.ts`, `config.matcher` (before fix):
  ```ts
  source: "/((?!_next/static|_next/image|favicon.ico).*)",
  missing: [
    { type: "header", key: "next-router-prefetch" },
    { type: "header", key: "purpose", value: "prefetch" },
  ],
  ```
- **Entry point and path:** any POST that sets `next-router-prefetch: 1` did not match, so `proxy()` never ran and `checkSameOrigin` was skipped. Next.js's own Server Action check still compares Origin to Host, but it lets a request with no Origin through with a warning.
- **Fix applied:** removed the `missing` clause; the proxy now runs on prefetches too (they gain a CSP header, which is harmless). An e2e test now posts with a cross-site Origin plus `next-router-prefetch: 1` and expects 403 (passes).
- **References:** [OWASP A01:2025](https://owasp.org/Top10/2025/A01_2025-Broken_Access_Control/), [OWASP CSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)

#### OWASP-A01-INFO-001: Origin check trusts `x-forwarded-host` (accepted)

- **Severity:** Informational. **Confidence:** Medium, because Vercel's handling of a client-supplied `x-forwarded-host` was not verified at runtime.
- **Location:** `lib/security/origin.ts:28`.
- **Notes:** Next.js uses the same header for its built-in Server Action check. In a CSRF attack the request comes from the victim's browser, which cannot set `x-forwarded-host`, so this does not create a CSRF path. A non-browser client can set any Origin it likes anyway, so the check is not meant to stop scripts; Turnstile and rate limits (Phase 4) do that. Re-verify if the site ever moves off Vercel or behind another proxy.
- **Manual check:** after the first Vercel deploy, `curl -X POST -H 'Origin: https://evil.example' -H 'X-Forwarded-Host: evil.example' https://<preview>/` should return 403.

### A02:2025 Security Misconfiguration

#### OWASP-A02-001: The proxy's 403 response carried no security headers (fixed)

- **CWE:** none; hardening observation (missing header on one response with no active content).
- **Severity:** Low. The body is the plain word "Forbidden", so there is nothing to frame or sniff.
- **Confidence:** High.
- **Location:** `proxy.ts:18` (before fix): `return new NextResponse("Forbidden", { status: 403 });`
- **Fix applied:** the 403 response now gets the same `securityHeaders()` list. The e2e test asserts `X-Frame-Options: DENY` on it (passes).
- **References:** [OWASP A02:2025](https://owasp.org/Top10/2025/A02_2025-Security_Misconfiguration/), [OWASP HTTP Headers Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html)

#### OWASP-A02-INFO-001: `style-src-attr 'unsafe-inline'` (accepted)

- **Severity:** Informational. **Confidence:** High.
- **Location:** `lib/security/csp.ts:65`.
- **Notes:** needed because React `style` props render as attributes, which nonces cannot cover. Style attributes cannot execute script; the residual risk is CSS-based UI redressing only if an HTML injection bug existed, and React escaping plus the script nonce make that unlikely. Recorded in `docs/decisions.md`.

Verified and not findings: `poweredByHeader: false`; `productionBrowserSourceMaps: false`; `'unsafe-eval'` added only when `NODE_ENV === "development"`; HSTS `max-age=63072000; includeSubDomains` (no `preload`, by decision); `X-Frame-Options: DENY` plus `frame-ancestors 'none'`; `nosniff`; `strict-origin-when-cross-origin`; Permissions-Policy denying camera, microphone, geolocation and browsing-topics; COOP `same-origin`; `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `upgrade-insecure-requests`; static assets get headers through `next.config.ts` `headers()`. The local e2e run confirmed all of these on a production build and found no CSP violations in the browser console.

### A03:2025 Software Supply Chain Failures

#### OWASP-A03-001: No delay before adopting newly published package versions (fixed)

- **CWE:** [CWE-1357 Reliance on Insufficiently Trustworthy Component](https://cwe.mitre.org/data/definitions/1357.html)
- **Severity:** Low. Exact pins and a frozen lockfile already stop silent drift; the gap was only the window right after a malicious publish, when Dependabot or a manual `pnpm add` could pull it in.
- **Confidence:** High.
- **Location:** `.github/dependabot.yml` (no `cooldown`), `pnpm-workspace.yaml` (no `minimumReleaseAge`).
- **Fix applied:** Dependabot `cooldown.default-days: 7` for npm and GitHub Actions; pnpm `minimumReleaseAge: 1440` (1 day). A 7-day pnpm value was tried first and rejected the current lockfile, because Next.js 16.4.5 was published 6 days ago; 1 day keeps installs working. Raise it once the lockfile ages.
- **References:** [OWASP A03:2025](https://owasp.org/Top10/2025/A03_2025-Software_Supply_Chain_Failures/), [OWASP Software Supply Chain Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Software_Supply_Chain_Security_Cheat_Sheet.html)

Verified and not findings: every `package.json` version is exact; `pnpm-lock.yaml` present; CI uses `pnpm install --frozen-lockfile`; `pnpm audit --prod --audit-level=high` in CI (local run: no known vulnerabilities); all three Actions pinned to full commit SHAs with version comments; workflow `permissions: contents: read`; `persist-credentials: false`; no secrets used in CI; `allowBuilds` denies install scripts for esbuild, sharp and unrs-resolver, and pnpm 12 blocks unlisted install scripts by default (observed during install).

### A04:2025 Cryptographic Failures

No findings. CSP nonces use `crypto.getRandomValues` with 128 bits (`lib/security/csp.ts`, `createNonce`). `buildCsp` rejects malformed nonces, which also blocks directive injection. `RATE_LIMIT_SALT` must be at least 32 characters. HTTPS is enforced by Vercel plus HSTS and `upgrade-insecure-requests`. No secret is hard-coded (pattern search over `.ts`, `.mjs`, `.json`, `.yml` found none); `.env*` is git-ignored except `.env.example`, which holds names only.

### A05:2025 Injection

No findings. No `dangerouslySetInnerHTML`, `eval` or `new Function` in scope; ESLint now errors on all three. Logs are emitted through `JSON.stringify` with an allow list of keys, which escapes CR and LF. Header values in `proxy.ts` are built only from constants and a validated nonce.

### A06:2025 Insecure Design

Not assessable yet: there are no forms, rate limits or business workflows in Phase 0. Prepared controls: Server Action body limit `64kb`; env schema requires the Turnstile, Upstash and salt variables in production.

### A07:2025 Authentication Failures

Not applicable: the site has no authentication by design. Account MFA (GitHub, Vercel, Resend, Cloudflare, Upstash, Cal.com, Google Workspace, registrar) is tracked in `docs/launch-checklist.md` and cannot be checked from the repository.

### A08:2025 Software or Data Integrity Failures

No findings. No deserialization of untrusted data. No webhooks. Actions pinned by SHA. No third-party scripts are loaded yet; the CSP allows none.

### A09:2025 Security Logging and Alerting Failures

No findings for Phase 0. `lib/security/log.ts` logs structured JSON with a fixed key allow list and a 200-character cap, and a unit test confirms an email address and an IP passed by mistake are dropped. Origin rejections are logged. Alerting on spikes is planned for Phase 4 and cannot be assessed yet.

### A10:2025 Mishandling of Exceptional Conditions

No findings. `checkSameOrigin` fails closed on a missing, `null` or malformed Origin and on a missing host. `getServerEnv()` throws on invalid configuration and lists variable names only (unit-tested to exclude values). Build scripts exit non-zero on failure. `error.tsx` and `global-error.tsx` do not exist yet; Next.js production defaults show no stack traces, and Phase 1 adds the custom pages.
